# 科技赋能师：AI 故事创想——未来的我

版本：0.1；日期：2026-10-24；状态：讨论与 Demo 验证稿。

新增游戏扩展规格：[体感切水果：课堂合作模式 PRD / Spec](specs/fruit-slice-prd.md)。该文件是开发前设计，尚未实现游戏。

## 1. 产品定义

面向幼儿园课堂的单人职业体验游戏。孩子想象二十年后的职业，以自己的卡通成人形象进入预制 3D 职业场景，利用摄像头动作识别驱动角色，理解 AI 如何从画面中寻找身体位置。

不将成人形象表述为真实未来长相的预测，不对职业能力或儿童身体动作做排名和评价。

## 2. 已确认决策

- 老师操作电脑连接大屏，单人轮流体验；每节课三十分钟。
- 动作流畅优先，统一卡通 3D 身体，保留部分个人面部特征。
- 照片可在取得监护人同意后使用云端处理；供应商、保留期限及删除机制另行确定。
- 先生成想象中的成人卡通脸部图片，再适配到简化 3D 头型，并与身体骨骼联动。
- 第一版以正面活动为主，接受限制虚拟头部转向，不追求自然侧脸和背身。
- 职业采用可扩展预制模板，不限于宇航员、科学家、工程师、消防员。
- 后续允许 AI 辅助创建新职业模板，需预览和验证后发布。

## 3. 待定条件

| 条件 | 对范围的影响 |
| --- | --- |
| 班级人数、年龄段 | 单轮时长、引导难度、是否全员体验 |
| 是否要求每人上台 | 现场拍照或课前准备的选择 |
| 电脑、浏览器、摄像头型号 | 性能基线、识别距离及设备适配 |
| 场地、光照与网络 | 站位范围、模型和资源预加载方案 |
| 人物生成预算与服务商 | 生成等待、相似度、照片处理方式 |
| 首批精修模板数量 | 美术资产与职业任务制作成本 |

以上未确定前，不承诺全班轮流时长、通用设备帧率或头像生成耗时。

## 4. 用户与学习目标

老师负责准备、选职业、切换视图、暂停、跳过及换人；孩子通过简单身体动作探索，旁观孩子参与观察与讲述。

课程后希望孩子能够：观察抬手时节点移动；理解摄像头提供画面、AI寻找身体位置；发现遮挡可能导致识别错误；说出想体验的职业和想做的一件事。试课时由老师记录观察结果，不保存儿童视频作为统计材料。

## 5. 课堂组织建议

建议开场三分钟、AI 骨架讲解四分钟、职业互动十八分钟、回顾五分钟。人数确定后调整。

容量必须包含入场、选人、换人和识别恢复。例：二十五人每人一分钟已占二十五分钟，不能同时满足上述课堂安排。若全员上台，应优先课前准备头像、缩短个人体验或分组轮换。

## 6. 核心流程

老师检查设备与预加载资源 → 选择本节课职业 → 选择默认形象或准备个人头像 → 孩子入场 → 识别与校准 → 展示骨架 → 职业变身 → 自由跟随 → 简单任务 → 定格反馈 → 清除当前个人内容并进入下一位。

提供无照片模式；头像生成失败可使用默认形象，不阻断体验。

## 7. 角色与头像规格

个人形象与职业分离，同一头像可跨职业复用，不因换职业重新生成。

生成素材要求：统一画风、正面平视、自然表情、脸部无遮挡、不生成职业帽子。头型提供侧面轮廓与后脑，模板负责帽子和头盔。

头像处理需包括裁切、位置对齐、背景处理、比例检查和肤色衔接。仅上传图片直接贴图是 Demo 验证能力，不代表该处理链已完成。

首版身体动作与轻微头部倾斜联动；不包含任意转头、独立表情捕捉、口型及完整 3D 个性化头部。用抬手、点头、侧倾、手臂经过脸前、头盔覆盖等场景检查穿模、拉伸、遮挡和连接处。

## 8. 职业模板契约

每个模板包含稳定 ID、名称、分类、封面、儿童引导语、职业介绍、统一骨骼角色、服装与道具、场景、动作映射与限制、任务触发规则、反馈及纪念画面、资源版本和可用状态。

职业目录可以扩充，但未完成的模板不在课堂中呈现为可体验。老师每节课可选择四至六种；这是建议配置，不限制职业库数量。

储备方向：太空探索、科学与自然、设计建造、医疗与救援、艺术表达、生活与农业。

Demo 提供八个外观变体：宇航员、科学家、消防员、医生、工程师、画家、厨师、园艺师。全部复用同一动作任务，不作为八套独立职业玩法验收。

## 9. 动作与任务要求

- 优先正面、原地、上半身动作，不要求跳跃、奔跑、深蹲或精细手指动作。
- 对动作进行平滑和幅度限制，避免突然扭曲。低置信度不驱动不可靠关节。
- 任务采用宽松阈值和短时保持，不因识别失败扣分；老师可协助完成。
- 缺失身体时停止累积进度，平缓回到等待姿势，温和提示入镜。
- 课堂版需要解决旁人入镜时的控制对象锁定，老师可重新指定；Demo 尚未实现身份锁定。
- 演示模式必须显著标明非实时识别；任务结果需区分演示完成和真人完成。

首个验证任务为双臂展开保持约三秒。后续制作宇航员平衡探索、工程师放置零件、科学家选择材料等职业专属规则。

## 10. 界面与老师操作

主界面包含职业选择、3D 舞台、个人形象、任务状态、摄像头入口。提供骨架开关、演示动作、暂停、任务重置、视角复位、关闭摄像头。

主界面以单屏课堂操作为目标，按视口高度分配满宽舞台，摄像头开启后与 3D 角色各占约一半宽度，不在页面下方追加视频区。真人观察窗为 9:16 竖向视窗，在右侧列居中，按可用高度计算宽度，避免超出舞台。横向源画面使用居中裁切填满竖框，骨架画布执行同样的裁切与镜像；不旋转、不拉伸人物。识别仍使用原始采集帧，竖向显示不代表扩大物理取景范围，需要引导体验者后退并保持身体居中。

职业、头像与任务详情统一放入默认关闭的设置弹窗，互动中只显示简短任务进度。3D 视野可在 60%–140% 之间调整，默认 85%；窗口尺寸变化和摄像头开关时保留该值，只有主动复位才恢复默认。

摄像头开启后进入专注互动布局：隐藏介绍区、不可用的演示动作按钮、底部相机介绍条和页脚，释放纵向空间。真人竖框尽可能占满舞台高度，画面标题、退出按钮和识别状态叠放在视频上，不额外压缩有效视频高度。关闭摄像头恢复准备界面。

最新布局调整：默认真人区域占舞台约 54%，窗口填满该列。默认“广角完整”显示完整采集画面并允许留边，避免竖屏裁切导致近似放大；“竖屏聚焦”作为可切换模式保留 9:16 取景。新增独立真人缩放 1.00×–1.80×，默认 1.00×，同步变换视频与骨架。此项优先于前述默认竖框布局，物理取景范围仍受硬件限制。

新增测试交互：顶部直接职业选择器，切换外观不重建个人脸部。可显式开启“实时换脸”，由本机视频中可见的眼耳鼻关键点估计脸部区域，动态更新 3D 头部的平面贴图。检测失效时冻结最后一张有效贴图并提示；关闭后恢复此前默认或上传头像，不保存实时脸部素材。该测试不是成人脸生成，不提供完整侧脸、口型形变或身份锁定。

竖向取景调整为“竖屏广角”：保持 9:16 外框，完整显示采集画面并允许留边。真人缩放扩为 0.60×–1.80×，视频和骨架使用相同变换。

真人骨架采用高对比描边、发光连线与显著关节点，手腕点使用不同颜色。只绘制可见且置信度合格的节点；髋部不入镜不应阻止绘制上半身。视频与节点画布使用相同比例和镜像变换，避免拉伸错位。

课堂版增加：课前检查、预加载状态、当前体验者切换、相机校准、暂停任务、手动推进、清空个人数据及可选纪念卡导出。

摄像头视图采用镜像交互。用于解释 AI 的真人节点来自检测结果，角色节点来自渲染骨骼，两者明确区分。

## 11. 数据与异常

默认不上传、不录制实时摄像头画面。云端头像生成只发送必要照片，明确处理方、用途、保留期限及删除机制，不默认用于训练。上传许可和现场摄像头许可分开处理。

权限拒绝、无摄像头、模型下载失败：提示原因，允许演示模式。头像生成或解码失败：允许重试或恢复默认。身体丢失：停止任务累积并提示。多人入镜：课堂版锁定当前体验者或暂停等待老师处理。低性能：关闭额外特效、降低推理频率和分辨率，保持状态可见。

## 12. 验收与度量

以下性能为候选目标，须指定设备、摄像头、分辨率和浏览器后验证，不是当前 Demo 已达到的结论。

| 项目 | 初步验收方式 |
| --- | --- |
| 渲染流畅度 | 约定基线设备上连续运行十分钟；候选目标稳定三十帧/秒，记录慢帧 |
| 跟随延迟 | 摄像头输入至屏幕动作端到端测量；候选目标 P95 不超过二百五十毫秒 |
| 任务可完成性 | 在同意参与的试课中记录尝试数、识别完成数及老师协助数，试课后确定阈值 |
| 识别恢复 | 正面重新入镜后候选目标两秒内恢复；记录失败和误切换 |
| 头像效果 | 代表性头像检查正面、轻微倾斜、遮挡和各职业帽子；明显错位不可发布 |
| 教学效果 | 老师观察孩子能否描述节点跟随、遮挡失效与职业愿望 |
| 模板扩展 | 新增职业不改变核心追踪逻辑，模板版本与资源可独立核对 |
| 隐私行为 | 网络请求检查实时视频和本地上传头像未被发送；关闭相机后释放所有媒体轨道 |

## 13. 版本路线

Demo：程序化 3D 风格、示例与上传脸部、职业外观变体、演示动作、单人身体识别及骨架展示。新增髋、膝、踝关节映射与受限身体侧转，以可信三维关键点驱动；腿部未入镜时回到站姿。身体转向限幅约 ±60°，头部反向补偿保持脸贴图接近正面，不作为背身跟踪能力承诺。

课堂 MVP：精修模板、个人卡通头像生成与适配、指定设备性能优化、职业任务、老师换人流程、对象锁定、预加载与照片生命周期。

后续：AI 辅助生成模板介绍、场景素材与规则配置，复用合格的骨骼和 3D 资产，经预览、兼容性检查及人工确认后发布。完全自动生成任意可驱动 3D 角色作为独立研究项。

当前 Demo 使用 Three.js 程序化角色及自定义二维骨骼映射，不使用 KalidoKit 或 VRM 资产。正式实现可按模型供应方式选择 VRM 或统一 glTF 骨骼，并将推理迁移至 Worker。

摄像头广角采集补充：优先请求原生画幅，不固定 16:9；启动后读取当前视频轨道的变焦能力，若范围有效则尝试最低值，并读取实际设置确认。成功、未开放、未确认或失败均在观察窗显示，控制失败不阻断采集。默认完整显示原始画面，真人缩放与镜头变焦分别处理。验收：有变焦设备实际值达到其最小值；无能力、约束拒绝或忽略时仍能正常采集且不误报成功；视频和骨架同步显示。独立超广角镜头切换不在本次范围。
