# 体感切水果：课堂合作模式 PRD / Spec

版本：0.1  
日期：2026-10-24  
状态：开发前规格稿；玩法方向已确认，识别参数及设备性能待试测  
所属产品：科技赋能师 · AI 故事创想 / 未来的我

## 1. 需求与已确认决策

在现有左侧 3D 职业角色舞台加入切水果游戏。水果出现在角色前方并向下掉落，孩子在摄像头前挥动双手，通过手部运动轨迹切开水果，右侧真人画面继续显示身体节点和连线。

用户已确认采用课堂模式：无炸弹、无漏切扣分，原地双手参与，以容易上手、合作收集和正反馈为优先。默认每轮六十秒，不设置排行榜、生命值、淘汰或失败结算。

本文件只定义规格，不表示游戏已实现。现有职业选择、人物脸部贴图、摄像头及身体跟随继续作为基础能力使用。

## 2. 产品目标与学习目标

| 目标 | 希望出现的行为 | 验证方式 |
| --- | --- | --- |
| 能参与 | 孩子经过简单引导即可切中水果 | 观察教程尝试次数与老师协助情况 |
| 有因果感 | 挥手、轨迹、水果切开在时间和位置上连续 | 观察孩子是否理解“我挥动了手，所以水果切开了” |
| 能理解 AI | 能看到右侧节点与左侧角色的动作关联 | 老师引导比较真人骨架、角色和轨迹 |
| 愿意合作 | 当前孩子收集水果，全班一起数水果 | 观察是否愿意接力、分享成果，不按个人成绩排名 |
| 便于带课 | 老师可提前结束、换人、调节节奏 | 试课记录换人时间和异常恢复步骤 |

不把动作速度、姿态标准程度或游戏命中量解释为儿童能力评价。

## 3. 用户、场地与使用前提

- 老师操作电脑并连接大屏，每次一名孩子控制角色，旁观孩子参与数数和鼓励。
- 每节课三十分钟，游戏只是其中一个互动环节；不假设全班每人都能体验完整六十秒。
- 孩子原地站在标记区域，周围留出能舒展双臂的空间。无需手持工具，无需跳跃、奔跑或大幅转身。
- 核心玩法只要求肩、肘、腕可见，腿部不入镜不阻止游戏；现有腿部跟随可独立保留。
- 摄像头、浏览器、电脑型号、孩子年龄和班级人数尚未确定，正式课堂验收前必须记录这些条件。

## 4. 关键取舍

### 4.1 保留切开的反馈，不引入惩罚压力

水果落地只是消失，不扣分、不播放责备音效、不打断游戏。不要求更快甩手，不用逼近身体极限的水果位置制造难度。

### 4.2 做真实 3D 展示，使用二维碰撞判定

水果、切开的两半、角色和场景使用 3D 呈现；首版水果运动限定在角色前方的交互平面，用舞台屏幕坐标完成碰撞判定。孩子不需要判断虚拟深度或向摄像头前后伸手才能命中。

### 4.3 挥动才切开，停留不切开

水果接触静止手部、识别抖动、重新入镜产生的坐标跳跃都不能计为有效切割。适度容错来自水果尺寸和碰撞半径，不以取消运动门槛换取命中率。

### 4.4 左侧游戏以实际显示的手部轨迹为准

判定发生在哪里，孩子就应当在哪里看见光点和拖尾。不能使用一套不可见的检测位置计分，再让角色的手出现在另一处。

## 5. 体验流程

1. 老师选择职业，准备默认头像、上传头像或现有实时脸部贴图。
2. 老师选择“自由体验 / 切水果”，进入游戏准备页。先不出正式水果，不消耗回合时间。
3. 检查单人站位、肩膀和至少一只手臂的可见性，显示左右手光点。
4. 摄像头体感模式识别到双手手腕高于各自肩膀（高出至少肩宽的 15%，肩肘腕置信度均不低于 0.6）后立即开始正式回合，不等待稳定一秒，不要求额外确认、练习或点击开始，也不显示开局倒计时。识别未就绪时不进入正式计时。
5. 鼠标演示模式保留可跳过的练习与三秒开局倒计时。摄像头模式一旦开局持续到计时结束或提前结束，不再暂停；放下双手仍继续出果和计时。
6. 正式回合出水果，孩子双手都可切；漏切无惩罚，全班一起数收集数量。
7. 到时或老师提前结束，停止出果和判定，展示本轮收集、当前职业、合作篮子总量与肯定性文案。
8. 老师选择“下一位”“再玩一次”或“返回自由体验”。下一位清理当前人的检测历史、光轨与脸部状态，不自动沿用前一位的实时脸贴图。

默认六十秒；老师可在准备阶段选择三十、四十五或六十秒。教程不计入回合；正式开始后连续计时，识别丢失、设置弹窗、摄像头关闭和后台时间均计入回合。

## 6. 信息架构与界面布局

### 6.1 互动页

保留左侧职业角色、右侧真人观察窗的单屏布局。切水果模式默认将更多空间分给游戏：左侧约 60%，右侧约 40%；自由体验继续沿用当前比例。此为首版布局建议，需按基线设备确认可读性。

| 区域 | 展示内容 | 约束 |
| --- | --- | --- |
| 顶部老师工具条 | 模式、当前职业、音效、提前结束、设置 | 核心操作不依赖挥手触发 |
| 左侧游戏舞台 | 角色、左右手光点、水果、切割反馈 | 水果不能生成在工具条或计数 UI 上 |
| 左侧游戏 HUD | 剩余时间、本轮收集、合作目标 | 大字、少文字，不显示排行榜 |
| 右侧观察窗 | 真人视频、身体节点、识别状态 | 支持广角完整和竖屏广角，完整画面允许留边 |
| 底部轻提示 | 当前操作提示 | 不挤占主要舞台高度 |

角色在水果后方，光轨在水果附近，HUD 最上层。淡化角色附近的装饰粒子，避免与水果混淆；保留脸部可辨识性，不将水果持续遮挡在脸上。

### 6.2 准备与设置

在老师设置面板配置时长、节奏、单手/双手可用性、声音、是否显示骨架。模式入口常驻舞台顶部，不放在设置弹窗；模式和职业可以在准备阶段选择；正式游戏中更换职业、布局或相机取景只清除旧输入轨迹，不中断回合。

正式回合不得要求孩子操作职业菜单、相机开关或弹窗。

### 6.3 结算

显示“我们一起收集了 X 个水果”和“这次你是职业名称”。可显示本轮水果分类数量，不显示漏切量、命中率、最快速度、名次或失败标签。未达到收集目标也给出中性或肯定反馈，不伪造已完成目标。

## 7. 水果与出果规则

### 7.1 首批内容

首版四种水果：苹果、橙子、西瓜、草莓。每四颗为一组打乱顺序，保证组内四种各出现一次。各类型共享碰撞规则与收集价值；美术大小差异不导致隐性的高难度或高分值。

每个水果具有：稳定实体 ID、类型、生成时间、位置、速度、碰撞半径、状态、切开效果引用。状态至少包含 `falling / sliced / expired / cleared`。

### 7.2 生成与落下

- 从左侧舞台上方的可达区域生成，短暂提示后自然落下；不采用从地面高速弹射的传统轨迹。
- 横向位置落在校准后的双手可达区内，避开舞台两侧边缘和角色脸部长期遮挡区。
- 第一颗正式水果生成在易于够到的中部位置，避免开局落在极边缘。
- 可带轻微横向漂移，但不强迫追逐、跨步或转身。
- 水果离开交互区域或寿命结束后自动移除，未切中不改变合作篮子。
- 每颗水果只能从未切状态转为已切一次。碎片和特效不再参与切割判定。

### 7.3 可达区域

准备阶段以肩部为中心，使用肩宽与实际挥手练习确定舒适区。水果主要落在腰部至额头附近、左右适度展开双臂可覆盖的范围。不要在头顶高处、膝盖以下或屏幕最边缘生成必须命中的水果。

校准不足时使用保守的中部区域；不能把“先做最大幅度动作”作为进入游戏的条件。

## 8. 手部输入与角色映射

### 8.1 数据来源

沿用现有 MediaPipe Pose 的肩、肘、腕关键点。左右腕作为两个独立输入通道，不要求握拳、伸指或精细手势。关键点置信度不足时，该只手不参与切割。

首版不增加独立手指识别模型。增加模型必须有明确收益和性能验证，不能仅为增加节点数。

### 8.2 坐标链路

1. 读取原始视频帧中的关键点及时间戳；视频缩放、留边和裁切不得改写识别数据。
2. 用身体关键点驱动角色；将角色左右腕的实际三维位置投影到左侧游戏画布。
3. 以投影后的手部位置绘制光点和光轨，并使用同一坐标完成水果碰撞。
4. 用原始手腕相对肩部的运动量辅助排除噪声，距离和速度按稳定的校准肩宽归一化。
5. 右侧视频和骨架继续采用完全一致的镜像、缩放、留边变换；这组显示变换不影响左侧碰撞。

游戏取景、角色手部光点与水果共享同一舞台坐标原点和尺寸，禁止使用整个网页宽度作为游戏坐标。

### 8.3 游戏中的视角约束

正式回合锁定左侧相机旋转与 3D 缩放，防止拖动视角或相机重排产生虚假刀轨。右侧真人缩放仅改变显示，不改变输入。

窗口尺寸、设备旋转、左右分栏比例或游戏相机改变时，重新计算投影和可达区，清除历史轨迹与旧位置水果，继续回合。保留已有收集量，时间照常流逝。

### 8.4 镜像与手部对应

动作像照镜子：孩子向画面左侧挥手，角色对应手部和光轨也向左移动。使用稳定的关节索引映射，不因左右手交叉而交换控制通道。

## 9. 切割判定

### 9.1 有效挥动

有效挥动同时满足：当前与上一有效采样点属于同一只手、检测连续、置信度达标、有足够位移与速度、没有不合理跳跃。静止状态和纯低幅抖动不激活光刃。

角色光点可以持续显示；有效挥动时增强为明显的亮色轨迹。无效采样后必须先建立新起点，不从旧位置跨屏连接。

### 9.2 连续碰撞

将同一只手连续两次有效位置组成线段，以轨迹宽度加水果半径构成扫掠区域。不能只检测当前点是否落入水果，否则低帧率时容易穿过水果却没有命中。

水果也在移动，需使用同一仿真时间区间内的水果位置进行检测；可用手相对水果的运动线段与原点圆求交，或固定步长子步进。只有有效挥动时间窗内的碰撞计分，防止水果自行落到静止光点上。

### 9.3 去重与边界

- 首个有效命中将水果标记为已切，立刻从可命中集合移除，再播放动画。
- 双手同一帧命中同一水果只收集一次。
- 一次挥动可切开多颗不同水果，每颗计一次。
- 隐藏、过期、重排清除和切开碎片不接受命中。
- 丢失跟踪后重新出现、切换模式与重设投影都清空两只手的历史位置。
- 超过允许采样间隔的点不能组成刀轨，不补算无效检测或后台期间的命中。

## 10. 反馈、目标与合作机制

### 10.1 切开反馈

命中后立即闪现切线，水果分成预制的两半，沿挥动方向分离并下落；配合局部切线高光、可见果肉与果籽截面、同色果汁溅射和命中处 +1。声音采用同步切裂、湿润爆开、低频冲击和水滴尾音的分层 Web Audio 合成；不同水果音高不同，普通单次命中不播放旋律。采用卡通表现，无刀具、血腥或强烈屏幕震动。

切开两半可用预制网格实现，不要求运行时任意几何切面。切线方向作为视觉参考，不承诺物理精确切割。

### 10.2 收集反馈

每切一颗收集数量增加一。初始合作目标建议为十二颗，目标达成后显示庆祝，并继续游玩至回合结束，不强制提前结束。

短时间连续切中可以显示“连续收集”，但不提供分数倍增，不要求为了连击加速。首版可以不做连击，仅保留稳定的命中反馈。

### 10.3 班级合作篮子

当前课堂的有效回合收集量可累计为合作篮子，只保留浏览器内存中的数量，不关联孩子姓名、照片或脸部特征。老师明确“加入合作篮子”后记录一次；重复点击同一回合不重复累计。

重新开始的练习回合不自动覆盖或重复累加已提交回合。老师可清空本堂合作篮子；刷新页面后归零需明确提示，不承诺跨设备保存。

## 11. 状态机

| 状态 | 可发生行为 | 退出条件 |
| --- | --- | --- |
| `setup` | 选职业、头像、时长、节奏，检查资源 | 选择切水果模式 |
| `calibrating` | 检查身体和手部，显示光点 | 摄像头检测双手举过肩膀立即开局；鼠标由老师进入练习 |
| `tutorial` | 慢速练习果，说明动作因果，不计正式收集 | 完成一次练习或老师跳过 |
| `countdown` | 三秒倒计时，不出正式水果 | 检测就绪且倒计时完成 |
| `playing` | 出果、挥动判定、收集、计时 | 时间结束或老师提前结束 |
| `results` | 展示成果，加入篮子，下一位或重玩 | 老师选择下一步 |
| `disposed` | 释放游戏实体、事件和临时资源 | 返回自由体验或重新进入 |

摄像头首次开局由双手举过肩膀触发，首帧生成第一颗水果，不经过练习和倒计时。举手只用于启动一次；开局后没有暂停状态或暂停按钮。双手放下、跟踪丢失、设置弹窗、换职业、摄像头关闭与后台均不中断本轮，连续计时至结束。

## 12. 异常与控制

| 情况 | 处理 |
| --- | --- |
| 一只手失效 | 该手立即停止判定并清除历史，另一只手可继续；显示轻提示 |
| 双手或控制者躯干持续丢失 | 停止无效手部的切割判定；水果与回合计时继续 |
| 另一人进入 | 尚无身份锁定，老师需保证单人站位；必要时提前结束本轮重新安排 |
| 摄像头关闭、轨道结束、权限失效 | 继续计时和出果，关闭无效切割输入；可重新开启摄像头或提前结束 |
| 页面切到后台 | 按实际经过时间计时，到时结束；返回时不集中补发水果或重放旧刀轨 |
| 长时间卡顿 | 计时继续，清除旧水果、特效和跨帧刀轨；不补发水果或补算命中 |
| 实时换脸检测失败 | 冻结当前脸部或使用默认脸，不因换脸失败停止有效身体游戏 |
| 水果资源失败 | 使用已验证的基础水果替代；仍不可用则停在准备页 |
| 无摄像头 | 可使用鼠标演示模式，持续标注“老师演示”，不与真人回合混同 |

鼠标演示必须按住并拖动才形成切割轨迹；悬停不切割。演示回合不得加入正式合作篮子。

当前 Demo 尚无可靠控制者身份锁定。因此“多人不误切换”是课堂版发布条件，不能用单人姿态检测参数代替身份锁定验收。

## 13. 首版建议参数

以下全部为开发初值，不是已完成儿童试测的结论。参数统一配置，不散落在渲染与碰撞代码中。

| 参数 | 建议初值 | 调整原则 |
| --- | --- | --- |
| 正式回合 | 默认 60 秒，可选 30 / 45 秒 | 按课堂人数安排 |
| 合作目标 | 12 颗 / 回合 | 不达标不失败 |
| 出果间隔 | 1.5–2.2 秒 | 首次体验从慢节奏开始 |
| 同时可切水果上限 | 3 颗 | 控制视觉负担与运算量 |
| 单果可交互时间 | 约 3–4 秒 | 由可达区高度和速度共同确定 |
| 水果直径 | 舞台短边的 11%–15% | 窄屏也需易看清，最终按现场像素检查 |
| 额外轨迹碰撞容错 | 水果半径的 20% | 不超出可见反馈过多 |
| 手腕有效置信度 | 0.6 | 与实际模型输出核对 |
| 摄像头开局等待 | 无额外等待 | 双手举过肩膀后立即开局，无需额外点击 |
| 速度归一化尺度 | 校准时稳定肩宽 | 游戏中不因转身持续缩小尺度 |
| 有效挥动速度 | 约 0.8 肩宽 / 秒 | 慢挥可用，排除细小抖动 |
| 有效位移 | 约 0.10 肩宽 / 150 毫秒 | 与速度共同验证，不以像素写死 |
| 最长有效采样间隔 | 180 毫秒 | 超过后重建起点 |
| 不合理跳跃 | 单次位移大于约 1.2 肩宽 | 先清轨迹，避免重新入镜误切 |
| 双手或躯干丢失 | 不暂停 | 无效手部立即停判，水果和计时继续 |
| 光轨寿命 | 120–180 毫秒 | 短且清晰，不遮挡水果 |
| 碎片 / 粒子寿命 | 约 0.5–0.8 秒 | 自动回收，低性能时减少数量 |

首版不自动提升难度，不因孩子动作幅度小而提高速度门槛。老师设置节奏后，回合中保持一致。

## 14. 模块与实现边界

| 模块 | 责任 |
| --- | --- |
| 游戏会话 | 状态机、连续回合计时、结果与回合 ID |
| 输入适配器 | 关键点置信度、连续采样、左右手、演示输入 |
| 舞台映射 | 角色腕投影、舒适区、镜像规则、布局变化重建 |
| 出果调度器 | 可复现随机序列、数量限制、生成范围和速度 |
| 碰撞系统 | 有效挥动、扫掠碰撞、去重和命中事件 |
| 场景表现 | 水果模型、两半动画、光轨、粒子、音效 |
| 老师界面 | 设置、开始、声音、提前结束、下一位 |
| 合作篮子 | 回合提交幂等、课堂内累计、清空 |

游戏独立于职业模板：职业提供角色和场景风格，游戏提供通用水果规则。切换职业不另写一套碰撞逻辑。首版不让不同职业拥有不同手长、命中优势或收集倍率。

所有游戏临时实体需可清理；退出游戏后角色继续使用原有自由体验功能。启动下一轮不能重复注册事件、创建第二个摄像头流或保留旧水果。

## 15. MVP 范围

### P0：首版开发必须具备

- 四种水果、受控掉落、切开两半与收集反馈。
- 单人、双手独立输入，腕部光点与轨迹，扫掠碰撞及去重。
- 准备、练习、倒计时、连续正式游玩、结算、下一位。
- 无炸弹、无扣分、无排行榜；课堂合作篮子与回合提交去重。
- 老师时长 / 节奏设置、角色职业复用、现有头像与骨架兼容。
- 检测丢失、相机关闭、后台切换、窗口重排的连续计时与轨迹重建。
- 明确标识的鼠标演示模式。

### P1：首版稳定后再评估

- 轻量连续收集提示、额外水果与职业主题水果篮。
- 课堂统一语音引导、可选成果卡。
- 经试测验证后的自动舒适区适配。

### 不包含

多人同时比赛、炸弹与生命机制、网络排行榜、复杂物理切面、全场行走追踪、专业深度相机支持、精细手指动作、通过面部识别给孩子排名、云端上传游戏视频。

## 16. 验收场景

| 编号 | 场景与操作 | 通过标准 |
| --- | --- | --- |
| A01 | 可靠跟踪下挥手穿过水果 | 可见轨迹经过水果，反馈和收集一致 |
| A02 | 手停住，水果自行落到光点 | 不发生有效切割 |
| A03 | 手部小幅抖动或低置信度跳跃 | 不误切；光轨不跨屏连接 |
| A04 | 低推理帧率下一次挥动跨越水果 | 连续线段检测可命中，不卡在单点判定 |
| A05 | 双手同时经过同一水果 | 仅收集一颗，只有一次切开事件 |
| A06 | 一次挥动经过两颗水果 | 每颗各收集一次，无重复计数 |
| A07 | 一只手暂时被遮挡 | 该手停判，另一只手可正常参与 |
| A08 | 双手 / 身体丢失、相机关闭或页面后台 | 计时和出果继续，无效输入与后台不发生命中，到时正常结算 |
| A09 | 跟踪恢复或窗口重排 | 清除旧轨迹，既有收集量保持，不出现跨屏切割 |
| A10 | 真人缩放、广角 / 竖屏切换 | 清除刀轨并重排，回合不中断；骨架对齐、左右方向一致 |
| A11 | 60 秒到时或老师提前结束 | 停止出果和命中，结果等于有效切割数 |
| A12 | 连续点击加入合作篮子 | 同一回合只累计一次 |
| A13 | 重玩、下一位、退出再进入共十轮 | 没有旧水果、旧刀轨、重复音效或额外摄像头流 |
| A14 | 目标未达成、全部漏切 | 正常结束，无扣分或失败羞辱反馈 |
| A15 | 鼠标演示模式 | 按住拖动可切，悬停不切；不计入真人合作篮子 |
| A16 | 不同职业、默认 / 上传 / 实时脸部 | 规则一致，角色外观不导致碰撞位置偏移 |

## 17. 性能与验证计划

基线电脑、摄像头、浏览器及画面分辨率确定后，记录身体推理耗时、渲染帧率、手部输入至反馈延迟、可见水果数和资源占用。

候选目标：稳定三十帧/秒；输入至切开反馈端到端 P95 不超过二百五十毫秒；状态明确为已命中后下一渲染帧即开始反馈。以上均需实测，不作为现有 Demo 的性能声明。

性能不足优先降低装饰特效、粒子数量和阴影开销；保留输入可靠性、扫掠碰撞与手部光点。不得通过降低到明显误切来维持表面帧率。

验证分三步：

1. 自动化验证几何碰撞、有效挥动门槛、状态机、连续计时、后台到时结束与提交幂等；用固定随机种子重放场景。
2. 在目标设备用鼠标演示和成年人摄像头操作验证边界与异常，不把结果等同于幼儿可用性。
3. 在完成必要许可的试课中验证慢挥、单手、身高差异、换人及教学理解；据此调节参数并冻结首版验收阈值。

## 18. 数据与隐私

实时视频、脸部贴图和身体轨迹默认只在本机使用，不上传、不录制、不持久保存。游戏统计只需临时回合 ID、收集数量、回合时长和性能采样，不保存逐帧关节点、脸部特征或姓名。

需要导出课堂数据或成果图片时作为独立能力另行定义，不隐含在启动游戏中。现有云端头像生成如未来接入，沿用独立的许可与照片生命周期，不与游戏摄像头上传混为一体。

## 19. 开发前仍需确认

- 班级人数与是否全员体验，决定默认六十秒是否符合课程安排。
- 目标电脑、摄像头、浏览器、场地距离和网络条件。
- 首次试课覆盖的年龄段，以及是否需要单手或坐姿参与的专门适配。
- 四种水果和两半动画的最终美术风格。
- 控制者身份锁定的实现方案；未完成前只可作为老师监督下的单人 Demo。

这些项目不妨碍先开发可评审 Demo，但不得以默认假设替代课堂成品验收。

## 20. 进入开发的建议顺序

先做可用鼠标测试的游戏状态机、出果和碰撞，再连接可靠的双手输入与角色光点，随后实现单屏老师控制和跟踪失效处理，最后接入职业皮肤、脸部贴图兼容、音效与合作篮子。

每一步先通过对应验收场景，再加视觉装饰；不先堆叠复杂特效再补输入稳定性。
